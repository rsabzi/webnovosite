## ۳) مسائل بحرانی (P0) — پیشنهاد رفع فوری

۱. **افشای اطلاعات شخصی:** `src/app/api/leads/route.ts` تابع `GET` دارد که **بدون هیچ احراز هویتی** ۲۰ لید آخر (نام، شرکت، موبایل، ایمیل، شرح پروژه) را JSON برمی‌گرداند. هر کسی با زدن `/api/leads` به داده‌های مشتریان شما می‌رسد. → حذف روت GET یا محافظت با هدر محرمانه سرور (بدون تغییر در منطق POST).
۲. **canonical سراسری:** `src/app/layout.tsx` مقدار `alternates: { canonical: "/" }` دارد؛ چون هیچ صفحه‌ای آن را override نمی‌کند، همه‌ی زیرصفحه‌ها به گوگل می‌گویند «نسخه‌ی اصلی من صفحه‌ی خانه است» → ریسک افت/حذف ایندکس صفحات `/services`, `/pricing`, … .
۳. **نبود rate limit و سقف طول ورودی** روی `/api/leads` و `/api/calculator` → اسپم فرم و هزینه‌ی بی‌دلیل.
۴. **نبود `error.tsx` / `global-error.tsx`:** هر استثنای رندر = صفحه‌ی سفید (بریف بخش ۱۶ صریحاً آن را ممنوع کرده).
۵. **توکن hard-code‌شده در پوشه‌ی قدیمی** (`6a1d18…/src/sections/Contact.tsx`) که در گیت ثبت شده است → اگر همان توکن در پروداکشن استفاده می‌شود، باید از @BotFather **revoke** شود.
۶. **عمومی‌بودن `/api/telegram/setup`** در پروداکشن (نمایش اطلاعات ربات و شمارش چت‌ها) → محدودسازی به توکن محیطی یا غیرفعال‌سازی در پروداکشن.

## ۴) مشکلات تبدیل (Conversion) — چرا بازدید به لید تبدیل نمی‌شود

- **قیف فعلی:** `Home → (CTA) → /contact (فرم ۶ بخشی)`. کاربر باید پیش از دریافت هر ارزشی، نام، شرکت، تلفن، بودجه و شرح پروژه بدهد.
- **نبود مرحله‌ی تشخیص:** هیچ‌جا از کاربر پرسیده نمی‌شود «نوع کسب‌وکارت چیست؟ حجم درخواستت چقدر است؟ کدام کار وقت تیمت را می‌خورد؟» — همان داده‌ای که هم به فروش کیفیت می‌دهد و هم به کاربر حس «کمک واقعی».
- **CTA واحد و متمایز وجود ندارد:** سه CTA با وعده‌های متفاوت (`جلسه تحلیل و دمو` / `ROI` / `سفارش اتوماسیون`) تمرکز را می‌شکند.
- **نبود CTA میانی:** بعد از بخش «قبل/بعد اتوماسیون»، بعد از شبیه‌ساز زنده و بعد از نمونه‌کارها، هیچ دعوت‌به‌اقدامی نیست تا کاربر گرم‌شده وارد شود.
- **فرم بدون Progress:** روی موبایل، طول فرم نرخ تکمیل را می‌شکند.
- **پیام موفقیت فرصت‌سوز است:** فقط می‌گوید «به تلگرام رسید»؛ بدون گام بعدی، بدون فایل/گزارش، بدون پیشنهاد زمان جلسه.

## ۷) SEO / Performance / Accessibility / Error Handling

**SEO**
- 🔴 canonical سراسری `/` (بند ۳-۲) — باید canonical فقط در صفحه‌ی خانه بماند و هر صفحه مقدار خودش را بدهد.
- 🟠 هیچ **JSON-LD** وجود ندارد. پیشنهاد: `Organization` + `ProfessionalService` + `FAQPage` (Home/FAQ) + `Service` و `BreadcrumbList` در صفحات خدمات/پروژه.

- 🟡 `sitemap.ts` برای همه صفحات `new Date()` می‌گذارد (بی‌ارزش‌شدن سیگنال تازگی).
- 🟡 صفحات قدیمی `alternates` اختصاصی ندارند → پس از رفع canonical، باید برای صفحه‌ی جدید (`/automation-check`) مقدار صریح گذاشته شود:

  - URL تمیز: `/automation-check`
  - صفحات نتیجهٔ شخصی (`/automation-check/result/*`) باید **`noindex`** باشند.

**Performance**
- `dynamic = "force-dynamic"` روی `/` بدون دلیل (سه کلاینت‌کامپوننت آن client-side هستند) → حذف و بازگشت به استاتیک/ISR.
- فونت‌ها با `@import` در CSS (render-blocking) → مهاجرت به `next/font` (بدون dependency جدید).
- صفحه‌ی `/automation-check` باید **سبک** بماند: هیچ کامپوننت سنگین Home (شبیه‌ساز/ROI/فرم) در آن bar نشود؛ آیکن‌ها از `lucide-react` موجود.

- AI تنها پس از Submit صدا زده می‌شود؛ سقف طول ورودی برای کنترل هزینه.

**Accessibility**
- افزودن `aria-live="polite"` برای وضعیت لودینگ/آماده‌بودن نتیجه، `aria-busy` روی دکمه‌ی Submit.
- بازگرداندن focus ring در نقاط `focus:outline-none` (یا `focus-visible:ring-2`).
- skip-link به محتوای اصلی؛ برچسب‌های `<label>` متصل با `htmlFor` در همه‌ی گام‌های فرم جدید؛ پیمایش کامل با کیبورد (Enter/Space روی گزینه‌ها، `Esc` برای بازگشت).

**Error Handling (بخش ۱۶ بریف)**

```ts
  id: serial("id").primaryKey(),
  businessType: text("business_type").notNull(),
  monthlyVolume: text("monthly_volume").notNull(),
  channels: jsonb("channels").notNull(),            // string[]
  currentProcess: text("current_process").notNull(),
  painTasks: jsonb("pain_tasks").notNull(),         // string[]

  diagnosis: jsonb("diagnosis").notNull(),

  automationFit: text("automation_fit"),            // high | medium | low
  status: text("status").notNull().default("new"),  // new | review_requested | contacted | closed
  createdAt: timestamp("created_at").defaultNow().notNull(),
});
```

> نکته‌ی عملیاتی: پروژه migration ندارد. برای ساخت جدول، یا `npx drizzle-kit push` اجرا می‌شود (با `DATABASE_URL` پروداکشن) یا یک SQL آماده‌ی idempotent (`CREATE TABLE IF NOT EXISTS`) تحویل داده می‌شود تا خودتان اجرا کنید.

```
AI_API_KEY=            # کلید سرویس هوش مصنوعی (فقط سرور)
AI_BASE_URL=           # پیش‌فرض: https://api.openai.com/v1 (قابل تنظیم برای درگاه‌های سازگار)
```

- نوار پیشرفت + «مرحله ۳ از ۸»؛ دکمه‌ی بازگشت همیشه در دسترس؛ Enter = ادامه؛ بدون Scroll جابه‌جا.

- دکمه‌ی ادامه تا پاسخ‌ندادن به گام‌های الزامی غیرفعال است (بدون خطای تحقیرآمیز).
- لودینگ: پیام‌های مرحله‌ای («بررسی پاسخ‌ها…»، «تحلیل کانال‌های ارتباطی…») + پیام اطمینان «صفحه را نبندید؛ اطلاعات شما ذخیره شده است».
- خطا: «در تحلیل اطلاعات مشکلی پیش آمد. اطلاعات شما از بین نرفته؛ لطفاً دوباره تلاش کنید.» + دکمه‌ی «تلاش دوباره» + گزینه‌ی «ارسال به تلگرام WebNovo».
- Mobile-first: دکمه‌های تمام‌عرض، حداقل ارتفاع لمسی ۴۴px، فونت ≥ ۱۶px در inputها (جلوگیری از zoom iOS).

- «نتیجه بررسی کسب‌وکار شما» → «۳ فرصت احتمالی برای اتوماسیون پیدا کردیم»
- هر فرصت: عنوان، بج اهمیت (بالا/متوسط/پایین)، توضیح کوتاه مشکل، راه‌حل پیشنهادی، پیچیدگی تقریبی.

## ۱۴) تصمیم‌هایی که از شما لازم دارم

۱. **سرویس هوش مصنوعی:** OpenAI سازگار (کلید دارید؟) یا درگاه سازگار با ایران (AvalAI/OpenRouter/…)، یا فعلاً فقط تحلیل قاعده‌محور با معماری آماده‌ی افزودن کلید؟
۲. **دامنه‌ی اصلاحات:** فقط افزودن ابزار جدید، یا همراه با رفع P0ها و اصلاح ادعاهای اغراق‌آمیز؟
۳. **ذخیره‌ی لید:** استفاده از Postgres موجود (ساخت جدول جدید لازم است) + تلگرام، یا فقط تلگرام؟
۴. **صدا و هویت برند:** یکدست‌سازی به صدای «تیم/شرکت نوین وب» (پیشنهاد من) یا حفظ روایت شخصی «رضا سبزی»؟

## ۱۵) ریسک‌ها و ملاحظات

- **دسترسی به سرویس AI:** کد روی Vercel (region `fra1`) اجرا می‌شود، پس محدودیت IP ایران اعمال نمی‌شود؛ با این حال انتخاب درگاه باید بر اساس کلید و قرارداد شما نهایی شود. در نبود کلید، ابزار با تحلیل قاعده‌محور کار می‌کند (بدون توقف قیف).
- **جدول دیتابیس:** قبل از انتشار باید با `drizzle-kit push` یا SQL دستی ساخته شود؛ دستور و SQL آماده تحویل داده می‌شود.
- **هزینه‌ی AI:** با سقف ورودی (≤ ~۲.۵KB) و خروجی محدود (حداکثر ۵ فرصت + متن‌های کوتاه) در هر لید، هزینه ناچیز است.
- **تغییر متن ادعاها:** محتوایی است، نه فنی؛ فقط با تأیید اعمال می‌شود و طبق بریف چیزی حذف نمی‌گردد (تعدیل دقیق‌تر می‌شود).
- **بدون dependency جدید:** کل ابزار با Next.js/React/Tailwind موجود و `fetch` سرور-side ساخته می‌شود.
