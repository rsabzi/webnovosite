# گزارش اجرای ارتقای سایت WebNovo به موتور جذب لید

**تاریخ:** ۱۴۰۵/۰۷/۰۷ (۲۰۲۶-۰۹-۲۹) · **پروژه:** `webnovo-portofolio` · **شاخه:** `arena/01a0ebd6-bot-company`
**وضعیت:** هر پنج فاز پیاده‌سازی‌شده و تست‌شده. تنها کاری که از سمت شما لازم است، تنظیم متغیرهای محیطی روی Vercel است (بخش ۶).

## ۱) خلاصه‌ی مدیریتی

سایت از «بروشور خدمات» به یک **قیف جذب مشتری B2B** تبدیل شد:

- **موتور اصلی:** صفحه‌ی جدید `/automation-check` با فرم هشت‌مرحله‌ای و تحلیل سروری (Google Gemini + موتور قاعده‌محور پشتیبان). کاربر **قبل از دادن اطلاعات تماس، ارزش دریافت می‌کند**.
- **CTA اصلی** «رایگان بررسی کن کجای کسب‌وکارت قابل اتوماسیون است» در ۶ نقطه‌ی منطقی سایت (هیرو، دو بخش میان‌صفحه، نوار اعلان، navbar، footer، خدمات، ماشین‌حساب) — بدون اسپم.
- **صداقت فروش:** اگر داده‌ها نشان دهد اتوماسیون برای کاربر اولویت نیست، تحلیل همین را صریح می‌گوید (حالت `automation_fit: low` + یادداشت صادقانه) و به‌جای فروش، «شروع از یک گام کوچک» پیشنهاد می‌شود.
- **ادعاهای اغراق‌آمیز حذف شد** (‎«+۶۵ پروژه»، «۹۹.۹٪ آپ‌تایم»، «۱.۸ ماه»، «۱۰۰٪»، «گارانتی بی‌قیدوشرط» و…) و لحن برند به **شرکت/تیم «نوین وب»** تغییر کرد (بدون اول‌شخص مفرد و بدون عبارت نادرست «ربات‌های صنعتی»).
- **امنیت و SEO:** کلید AI فقط سمت سرور، سقف نرخ روی همه‌ی POSTها، محدودسازی مسیرهای مدیریتی با توکن، متادیتا/canonical/sitemap/JSON-LD اصلاح‌شده، صفحه‌های خطا و ۴۰۴ اختصاصی.

**۷ فایل جدید کتابخانه/کامپوننت، ۲ مسیر API جدید، ۲۷ فایل ویرایش‌شده — بدون هیچ وابستگی npm جدید.**

## ۳) معماری پیاده‌شده

```
src/lib/
  automation-questions.ts   ← ۸ گام، گزینه‌ها، اعتبارسنجی هر گام (منبع حقیقت فرم)
  automation-diagnosis.ts   ← اسکیمای تشخیص + موتور قاعده‌محور + پرامپت/فراخوانی Gemini + اعتبارسنجی/کلمپ خروجی
  validation.ts             ← اعتبارسنجی سرور (موبایل، ایمیل، نرمال‌سازی)
  rate-limit.ts             ← سقف نرخ درون‌حافظه‌ای + کلید ناشناس درخواست
  analytics.ts              ← رویدادهای آنالیتیکس (در نبود سرویس، بی‌اثر و بی‌آسیب)

src/app/api/automation-check/route.ts          ← POST تحلیل + GET ?probe=1 (سلامت پیکربندی)
src/app/api/automation-check/review/route.ts   ← POST درخواست بررسی دقیق توسط تیم

src/components/automation-check/
  AutomationCheckWizard.tsx  ← فرم ۸ مرحله‌ای، ذخیره‌ی draft و نتیجه در sessionStorage
  DiagnosisResult.tsx        ← UI نتیجه (گذشته‌ی صادقانه، فرصت‌ها، گام بعدی، CTAها)
src/components/AutomationCheckCta.tsx          ← CTA قابل‌استفاده‌ی مجدد (هیرو/فشرده)
src/app/automation-check/page.tsx              ← صفحه‌ی ابزار + متادیتای اختصاصی
```

**جریان داده:** فرم → `POST /api/automation-check` → اعتبارسنجی → سقف نرخ → تحلیل (Gemini با `responseSchema`؛ در هر خطا → موتور قاعده‌محور) → پاسخ JSON تمیز به کلاینت → رندر نتیجه + اعلان تلگرام برای تیم.
خروجی خام مدل هرگز به کاربر نشان داده نمی‌شود و حتی به کلاینت هم فرستاده نمی‌شود؛ ابتدا در سرور اعتبارسنجی و به ساختار موردنظر تبدیل می‌شود.

## ۴) آنچه کاربر می‌بیند (تجربه‌ی فارسی و موبایل‌محور)

- **صفحه‌ی اصلی:** هوک دارک و مینیمال؛ CTA اصلی هیرو + مسیر روشن «چالش → راه‌حل نوین وب → نمونه‌ی واقعی → تشخیص رایگان → اعتماد → درخواست پروژه».
- **فرم:** «مرحله ۳ از ۸» + نوار پیشرفت + درصد، سؤال‌های تک‌انتخابی/چندانتخابی/متنی/تماس، راهنمای اعتبارسنجی زنده («برای تحلیل دقیق‌تر، حداقل N کاراکتر دیگر…»)، دکمه‌ی «مرحله قبل/بعد»، «شروع از ابتدا».
- **نتیجه:** «نتیجه بررسی کسب‌وکار شما» → «۳ فرصت احتمالی برای اتوماسیون پیدا کردیم» → کارت هر فرصت (مسئله، راه‌حل، اهمیت، پیچیدگی) → «پیشنهاد WebNovo برای شما» → CTAهای «درخواست بررسی توسط WebNovo» و «بازگشت به خدمات WebNovo».
- **حالت صادقانه:** وقتی حجم/نوع کار توجیه نداشته باشد، برچسب «اتوماسیون گسترده فعلاً اولویت شما نیست» + یادداشت صریح نمایش داده می‌شود.
- **حالت‌های خطا (پیام انسانی، بدون صفحه‌ی سفید):** خطای شبکه، پاسخ خالی/نامعتبر سرور، خطای اعتبارسنجی، و بازگشت کاربر در میانه‌ی کار. در همه‌ی حالت‌ها متن «اطلاعات شما از بین نرفته؛ لطفاً دوباره تلاش کنید» + دکمه‌ی «تلاش دوباره» + مسیر جایگزین تلگرام + ذخیره‌ی خودکار پاسخ‌ها.

**رویدادهای آنالیتیکس:** `automation_cta_click`، `automation_form_started`، `automation_form_completed`، `automation_result_viewed`، `lead_submitted`، `project_request_clicked` (در `analytics.ts`؛ در نبود ابزار آنالیتیکس، به‌صورت بی‌اثر اجرا می‌شوند و سایت را کند نمی‌کنند).

## ۶) کاری که شما باید انجام دهید (چک‌لیست استقرار)

در **Vercel → Project → Settings → Environment Variables** (برای Production و Preview):

| متغیر | مقدار | توضیح |
|---|---|---|
| `GEMINI_API_KEY` | کلید AI Studio شما | **فقط سرور**؛ هرگز در ریپو/کلاینت قرار نمی‌گیرد |
| `GEMINI_MODEL` | خالی بگذارید | کد خودش جدیدترین مدل متنی فلشِ در دسترس کلید را پیدا می‌کند |
| `NEXT_PUBLIC_SITE_URL` | `https://www.webnovo.ir` | برای canonical/sitemap/OG |
| `LEADS_ADMIN_TOKEN` | یک رشته‌ی تصادفی طولانی | لازم برای `GET /api/leads`، `/api/telegram/setup` |
| `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` | مقادیر موجود شما | اعلان لیدها |

نکات:
- اگر شک دارید کلید قبلی در جایی لو رفته باشد، از AI Studio یک کلید تازه بسازید و کلید قدیمی را باطل کنید. کلید جدید را **فقط در پنل Vercel** وارد کنید و در چت/کد قرار ندهید.
- بعد از دیپلوی، اول `probe` را بزنید (بخش ۶.۱) و بعد یک‌بار خودتان فرم را پر کنید؛ روی نتیجه باید نشان سبز «تحلیل اختصاصی با هوش مصنوعی (Gemini)» دیده شود.
- فایل `.env.local` در سندباکس فقط برای تست محلی است و در Git نیست.

## ۶.۱) اطمینان از اینکه تحلیل واقعاً با هوش مصنوعی انجام می‌شود

اگر نتیجه‌ی ابزار «قاعده‌محور» به نظر می‌رسد یا برای کسب‌وکارهای مختلف شبیه هم است، یکی از این دو علت را دارد:

۱. **کلید در محیط اجرا تنظیم نشده است** (شایع‌ترین حالت). تا وقتی `GEMINI_API_KEY` در Vercel نباشد،
   سیستم طبق طراحی به موتور قاعده‌محور برمی‌گردد و همین را روی صفحه‌ی نتیجه هم با نشان زرد
   «تحلیل قاعده‌محور — هوش مصنوعی در دسترس نبود» به کاربر می‌گوید.
۲. **مدل انتخابی برای این کلید در دسترس نیست** — علت واقعی کشف‌شده در ۲۹ سپتامبر ۲۰۲۶:

```json
HTTP 404: {"error":{"code":404,"message":"This model models/gemini-2.5-flash is no longer available to
new users. Please update your code to use models/gemini-3.8-flash for the latest features"}}
```

گوگل از ۱۸ سپتامبر ۲۰۲۶ دسترسی پروژه‌های جدید به سری ۲.۵ را محدود کرده و برای پروژه‌های جدید
`gemini-3.8-flash` را پیشنهاد می‌کند؛ بنابراین هر تحلیلی به مسیر قاعده‌محور می‌افتاد.
۳. **فراخوانی مدل در آن لحظه شکست خورده است** (قطعی موقت، محدودیت نرخ، پاسخ بریده‌شده).

برای رفع دائمی این کلاس از خطا، این‌ها پیاده‌سازی شد:

- **کلید فقط از متغیر محیطی `GEMINI_API_KEY` خوانده می‌شود** (سمت سرور). کلید هرگز در کد/ریپو/باندل کلاینت نیست.
- **انتخاب خودکار مدل:** اگر مدل تنظیم‌شده بازنشسته/در دسترس نباشد، فهرست واقعی مدل‌های همین کلید از
  `GET /v1beta/models` خوانده و جدیدترین مدل متنی فلش انتخاب می‌شود؛ سپس زنجیره‌ی
  `3.8 → 3.7 → 3.6 → 3.5 → 3.5-flash-lite → 2.5-flash` امتحان می‌شود.
- **پارامتر تفکر مخصوص هر نسل:** نسل ۳ = `thinkingLevel: low|medium|high` و نسل ۲.۵ = `thinkingBudget`
  (ارسال اشتباه خطای ۴۰۰ می‌دهد؛ کد بر اساس نسل مدل تصمیم می‌گیرد).
- **دو قالب خروجی ساختاریافته:** `responseSchema` و در صورت رد شدن، `responseFormat.text.schema`.
- **مقاوم در برابر اوج تقاضا (۵۰۳) و محدودیت نرخ (۴۲۹):** مدل شلوغ ۶۰ ثانیه کنار گذاشته می‌شود و
  درخواست در همان لحظه به مدل دیگری می‌رود (حداکثر ۳ مدل در هر فراخوانی، با احترام به `Retry-After`).
  اگر همه‌ی مدل‌ها شلوغ بودند، کاربر می‌تواند از دکمه‌ی «تلاش دوباره برای تحلیل هوش مصنوعی» — بدون
  پر کردن دوباره‌ی فرم — تحلیل AI را دوباره بگیرد.
- **تلاش مجدد هوشمند:** تا ۳ تلاش با بودجه‌ی زمانی کل ۲۶ ثانیه؛ خطاهای گذرا (شبکه، 429، 5xx،
  پاسخ خالی/بریده) تکرار می‌شوند و خطاهای پیکربندی (کلید نامعتبر/۴۰۰/۴۰۱/۴۰۳) بی‌درنگ متوقف می‌شوند.
- **بودجه‌ی خروجی بزرگ‌تر (۸۱۹۲ توکن) + مهار بودجه‌ی تفکر (۱۰۲۴)** تا متن فارسی مدل در میانه‌ی راه بریده نشود.
- **پرامپت اختصاصی‌تر:** مدل موظف است نوع کسب‌وکار، حجم، کانال‌ها و «مشکل اصلی» کاربر را با کلمات خودش
  در خلاصه بیاورد و هر فرصت را به کارهای زمان‌بر یا ابزارهای فعلی همان کسب‌وکار گره بزند (تحلیل عمومی ممنوع).
- **نشان موتور تحلیل روی صفحه‌ی نتیجه:** «تحلیل اختصاصی با هوش مصنوعی (Gemini)» یا «تحلیل قاعده‌محور…» —
  پس همیشه می‌دانید کاربر چه چیزی دیده است.
- `maxDuration = 30` روی مسیر API تا سقف زمان تابع Vercel با بودجه‌ی تلاش مجدد هماهنگ باشد.

**تأیید سلامت روی سرور (بدون افشای کلید):**

```bash
curl -s "https://www.webnovo.ir/api/automation-check?probe=1"
```

پاسخ شامل این فیلدهای عیب‌یابی است: `ok` · `model` (مدل واقعیِ پاسخ‌دهنده) · `availableModels` ·
`environment` (production/preview/local) · `branch` · `commit` · `keyPresent` · `keyLooksValid` · `hint`

```json
{ "ok": true, "model": "gemini-3.8-flash", "environment": "production", "commit": "…",
  "availableModels": ["gemini-3.8-flash", "gemini-3.7-flash", "…"],
  "keyPresent": true, "keyLooksValid": true, "error": null }
```

> ⚠️ **مهم‌ترین دام:** متغیرهای Vercel به تفکیک محیط (`Production` / `Preview` / `Development`) تعریف
> می‌شوند. اگر `GEMINI_API_KEY` فقط برای `Preview` ساخته شود، دامنه‌ی اصلی که روی Production سرویس
> می‌دهد آن را نمی‌بیند و همیشه تحلیل قاعده‌محور می‌ماند. همچنین متغیرهای محیطی فقط روی **دیپلوی‌های
> جدید** اثر می‌گذارند، پس بعد از افزودن/ویرایش کلید حتماً **Redeploy** لازم است.

| نشانه | علت | راه‌حل |
|---|---|---|
| `probe` → `keyPresent:false` و `environment:"production"` | کلید فقط برای محیط دیگری (مثلاً Preview) ساخته شده | ویرایش متغیر → تیک `Production` و `Preview` → Save → **Redeploy** |
| `probe` → `keyPresent:false` | کلید روی Vercel ساخته نشده | `GEMINI_API_KEY` را برای Production و Preview بسازید و Redeploy کنید |
| `probe` → `keyLooksValid:false` | کوتیشن/فاصله در مقدار یا کلید غیرِ AI Studio | مقدار را دوباره و بدون کوتیشن از AI Studio کپی کنید |
| `probe` → `commit` قدیمی | دیپلوی جدید ساخته نشده | Redeploy کنید |
| `probe` → `HTTP 404 … no longer available to new users` | مدل انتخابی برای کلیدهای جدید بازنشسته شده | `GEMINI_MODEL` را خالی بگذارید (انتخاب خودکار مدل) |
| `probe` → `HTTP 400/401/403` | کلید نامعتبر/محدود | کلید تازه از AI Studio بسازید |
| `probe` → `fetch failed` | دسترسی خروجی سرور به Google بسته است | `GEMINI_API_BASE_URL` نباید تنظیم باشد (فقط برای تست محلی است) |
| نشان زرد روی نتیجه‌ی کاربر | کلید نبوده یا هر ۳ تلاش شکست خورده | لاگ‌های Vercel → Functions را ببینید: با `[automation-check] AI attempt …` شروع می‌شوند |
